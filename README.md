## Описание:
Выкладываем проект на GitHub и ведем разработку по GitFlow.
Учитываем рекомендации PEP 8, используя линтеры делаем атомарные коммиты.

## Установка зависимостей:
1. Клонируйте репозиторий:
    ```
    git clone https://github.com/konstantin-X-42/project_Home_10-1
    ```
2. Установите зависимости, идентичные файлу poetry.lock если лока нет на основе pyproject.toml
    ```
    poetry install
    ```
### зависимости для тестирования, проверки стиля кода или отладки:

3. Установите библиотеку фреймворк pytest — инструмент для написания тестов
    ```
    poetry add --group dev pytest
    ```
4. Установите библиотеку для анализа покрытия кода при проведении тестирования
    ```
    poetry add --group dev pytest-cov
    ```

## Использование:
#### **В проекте реализованы следующие функции в модулях:**

## **модуль masks.py**
### ***1. маскировка цифр номера карты пользователя в формате: 8990 92** **** 5229***
```
        get_mask_card_number()
```
##### функция в аргументе принимает:
- строку - str
- набор целых чисел - int

##### функция обрабатывает исключения:
- **Error_01** - ошибочное количество символов в номере карты
- **Error_02** - введён не допустимый тип данных или не числовой символ в номере карты
- **Error_03** - не введён номер карты
###### Аргументы функции:
```
    get_mask_card_number('7000792289606361')
```
###### функция возвращает строку - str скрытого номера карты:

###### 7000 79** **** 6361

```
        def mask_account_card()
```

- строку - str в формате: "Maestro 1596837868705199"

                                "Visa Classic 6831982476737658"
                                "Visa Platinum 8990922113665229"
                                "Visa Gold 5999414228426353"


##### функция в себе обработку исключений не ведёт, импортирует исключения из функций модуля masks.py:
- **Error_01** - не верное количество символов в номере карты
- **Error_02** - введён не допустимый тип данных или не числовой символ в номере карты
- **Error_03** - не введён номер карты
- **Error_04** - не верное количество символов в номере счёта
- **Error_05** - введён не допустимый тип данных или не числовой символ в номере счёта
- **Error_06** - не введён номер счёта
###### Аргументы функции:
```
    def mask_account_card('Счет 64686473678894779589'):
```
###### функция возвращает строку - str скрытого номера карты или счёта в зависимости от поданного аргумента в функцию:

###### 7000 79** **** 6361  - карта
###### ** 4305              - счёт

### ***4. возвращает дату в формате: 'ДД.ММ.ГГГГ'***
```
        get_date() -> str:
```
##### функция в аргументе принимает:
- строку - str в формате: '2024-03-11T02:26:18.671407'

- **Error_10** - в функцию подаётся пустая строка
###### Аргументы функции:
```

```
###### функция возвращает отфильтрованый формат даты:  ДД.ММ.ГГГГ

###### 11.03.2024

## **модуль processing.py**
### ***5. фильтрация по статусу***
```
        filter_by_state()
```
##### функция в аргументе принимает:
- массив: список словарей - [{dict1}, {dict2}, ...]  или картеж словарей - ({dict1}, {dict2}, ...)
- критерий фильтра массива по умолчанию - 'EXECUTED' или 'CANCELED' ключа 'state'.

##### функция обрабатывает исключения:
- **Error_11** - в функцию не подаются аргументы
- **Error_12** - в аргументе функции, key в словарях или в одном из словарей отсутствует
###### Аргументы функции:
```
    filter_by_state([{'id': 594226727, 'state': 'CANCELED', 'date': '2018-09-12T21:27:25.241689'},
        {'id': 41428829, 'state': 'EXECUTED', 'date': '2019-07-03T18:35:29.512364'},
        {'id': 939719570, 'state': 'EXECUTED', 'date': '2018-06-30T02:08:58.425572'},
        {'id': 615064591, 'state': 'CANCELED', 'date': '2018-10-14T08:21:33.419441'}], 'CANCELED')
```
###### функция возвращает отфильтрованый список словарей:  [{dict1}, {dict2}, ...]

###### [{'id': 594226727, 'state': 'CANCELED', 'date': '2018-09-12T21:27:25.241689'},
###### {'id': 615064591, 'state': 'CANCELED', 'date': '2018-10-14T08:21:33.419441'}]

## Тестирование

В проекте используется фреймворк `pytest` для проверки корректности работы функций и обработки ошибок.

### Запуск тестов
Для запуска всех тестов выполните:
```
poetry run pytest
```

### Анализ покрытия кода (Coverage)
Чтобы узнать, насколько полно код покрыт тестами, используйте `pytest-cov`:
```
poetry run pytest --cov=src
```

### Список проверяемых сценариев:
Проект включает в себя систему валидации данных с возвратом специфических кодов ошибок.

#### Работа с картами:
* **Error_01**: Ошибочное количество символов в номере карты.
* **Error_02**: Недопустимый тип данных или нечисловой символ.
* **Error_03**: Номер карты не введен (пустое значение).

#### Работа со счетами:
* **Error_04**: Ошибочное количество символов в номере счета.
* **Error_05**: Недопустимый тип данных или нечисловой символ.
* **Error_06**: Номер счета не введен (пустое значение).

#### Работа с датами:
* **Error_07**: В дате присутствует нечисловой символ.
* **Error_08**: Значения цифр за пределами формата даты (например, месяц > 12).
* **Error_09**: Передан недопустимый тип данных.
* **Error_10**: Передана пустая строка.
